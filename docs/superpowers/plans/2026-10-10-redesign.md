# Algoritm CRM Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the whole CRM to the approved "ink and amber", Nothing-inspired design with light, dark and auto themes and a phone-first navigation, without changing any behaviour.

**Architecture:** Semantic colour tokens (CSS variables switched by `data-theme` on `<html>` and by `prefers-color-scheme` in Auto) are exposed to Tailwind v4 via `@theme inline`. Every hard-coded `slate/brand/sidebar/rose/emerald/sky/amber` class is migrated to those tokens. The theme is stored in a `theme` cookie that the root layout reads, so the server renders the right theme on first paint. Motion is pure CSS (keyframes, transitions, `(app)/template.tsx`).

**Tech Stack:** Next.js 15 App Router, React 19, Tailwind CSS v4, `next/font/google`, lucide-react, Node's built-in test runner via `tsx --test` (already installed; no new dependencies).

**Spec:** `docs/superpowers/specs/2026-10-10-redesign-design.md`

## Global Constraints

- No new runtime dependencies. No changes to data, permissions, routes, server actions, or Uzbek copy.
- Brand colours: amber `#FFBE00`, ink `#161817`. Light page `#F4F2EE`, dark page `#000000`. All other values come from the spec §3 colour table.
- Amber is a fill behind ink (`#161817`) text; amber as text is allowed only on dark backgrounds.
- At most one amber-filled button per view.
- Fonts: Outfit (400/500/600) for UI, Doto only for display numbers, JetBrains Mono (uppercase, wide tracking) for labels. Loaded via `next/font/google`.
- Motion: 150–250 ms, `cubic-bezier(.2,.8,.2,1)`, all disabled under `prefers-reduced-motion: reduce`.
- Theme values: `"light" | "dark" | "auto"`, default `"auto"`, cookie name `theme`, max-age one year.
- Breakpoints: phone < 768px, tablet 768–1023px, desktop ≥ 1024px.
- Phone tab priority: `/` → `/schedule` → `/groups` → `/students` → `/leads` → `/payments`; three tabs plus Menu.

## Review Focus

1. **A bad or missing `theme` cookie** (e.g. `theme=purple`, empty) — should fall back to Auto, never crash or render no theme. Pinned by `parseTheme` tests in Task 1.
2. **A user with fewer than three allowed tab pages** (e.g. cashier with only payments) — the tab bar should show what they have plus Menu, with no empty slots or duplicates. Pinned by `phoneTabs` tests in Task 3.
3. **Dashboard opened by a user without `dashboard.view`** — `/` redirects elsewhere, so `/` must not be offered as a tab to that user. Pinned by `phoneTabs` test in Task 3.
4. **Long names on phones** (group, student, course names) — must truncate, not push the layout sideways. Checked at 375px on every page batch (Tasks 6–10 verification).
5. **Leftover hard-coded colours on rarely visited pages** (settings/mcp, no-access, error) — they would look broken in dark mode. Pinned by the `check:colors` script, which fails until the sweep in Task 11.
