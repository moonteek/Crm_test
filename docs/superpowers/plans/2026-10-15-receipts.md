# Receipts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Print, download as PDF and reprint payment receipts, with a "Chek" settings tab and live preview.

**Architecture:** One pure module (`src/lib/receipt.ts`) turns stored settings + one payment into receipt lines; the
settings preview, the print page and the PDF route all draw from it. Settings live in a new generic `Setting` table
(key `receipt`, JSON). The PDF is drawn server-side with pdf-lib (Courier). The payment dialog returns the new id and
offers "Chek chiqarish".

**Tech Stack:** Next.js 15 App Router, React 19, Prisma 6 (SQLite, `db push`), zod 4, node:test via `npm test`,
pdf-lib (new), sharp (already installed, used once to make the default logo PNG).

**Spec:** docs/superpowers/specs/2026-10-15-receipts-design.md

## Global Constraints

- Paper width: 80 mm (default) or 58 mm. Summa always shown. Settings: `staff.manage`.
- Logo: PNG or JPG data URL, ≤ 300 KB; SVG refused; default = built-in Algoritm logo PNG in `public/receipt-logo.png`.
- Defaults: name "Algoritm", no phone/address, 80 mm, logo shown, every line on.
- Receipt access: `payments.view` or `payments.create` and the payment's student in the user's scope; otherwise 404.
- Receipt is black on white in every theme; colours elsewhere use theme tokens (`npm run check:colors`).
- Copy (Uzbek): "Chek chiqarish", "PDF yuklab olish", "Chop etish", "Yopish", "To'lov saqlandi", "Chek №",
  "Chek topilmadi", "Rahmat!", "Chek sozlamalari", "Chek ko'rinishi", "Logotipni ko'rsatish".
- Stop the dev server before `npm run db:push` (Windows DLL lock).

## Review Focus

- Stored setting JSON that is broken, partial or from an older shape → defaults per field, page never crashes (Task 1 test).
- Very long student / group / centre names on 58 mm → wrapped within the width, never cut mid-number or overflowing (Task 1 test).
- A payment whose group was deleted, or taken before "Mas'ul" was recorded → "—", receipt still prints (Task 1 test).
- A user who can't see the student opening `/payments/<id>/receipt` or `/pdf` by guessing ids → 404 (Task 3 browser + route check).
- Uploading a non-image, an SVG or a 2 MB photo as logo → refused with a clear message, old logo kept (Task 1 test + Task 2 browser).

### Task 1: Receipt core (settings model, lines, data)

**Files:**
- Modify: `prisma/schema.prisma` (model `Setting { key String @id; value String; updatedAt DateTime @updatedAt }`)
- Create: `src/lib/receipt.ts`, `src/lib/receipt.test.ts`, `src/lib/receipt-db.ts`
- Create: `public/receipt-logo.png` (from the Algoritm logo SVG in `src/components/brand/Logo.tsx`, black, 256 px wide, via a one-off sharp script in the scratchpad)

**Interfaces:**
- Produces (`receipt.ts`, pure, client-safe):
  - `RECEIPT_LINES = ["number","time","student","teacher","taker","group","month","method"] as const`; `type ReceiptLine`
  - `type ReceiptSettings = { name: string; phone: string; address: string; paper: 80 | 58; showLogo: boolean; logo: string | null; lines: Record<ReceiptLine, boolean> }`
  - `RECEIPT_DEFAULTS: ReceiptSettings`; `parseReceiptSettings(json: string | null): ReceiptSettings`
  - `type ReceiptData = { id: number; date: Date; student: string; teacher: string | null; taker: string | null; group: string | null; month: Date | null; method: string; amount: number }`
  - `receiptText(s: ReceiptSettings, d: ReceiptData): { header: string[]; rows: [string, string][]; total: [string, string]; footer: string; width: number }` — `width` = characters per line: 48 at 80 mm, 32 at 58 mm; every row's label + value fits `width` (value wraps onto following lines when too long).
  - `logoProblem(dataUrl: string): string | null` — null when PNG/JPG data URL ≤ 300 KB, else the Uzbek message.
  - `SAMPLE_RECEIPT: ReceiptData` (for the settings preview).
- Produces (`receipt-db.ts`, server-only): `getReceiptSettings(): Promise<ReceiptSettings>`, `saveReceiptSettings(s: ReceiptSettings)`, `receiptDataFor(user: CurrentUser, paymentId: number): Promise<ReceiptData | null>` (null when missing or not allowed; teacher via `teacherOn(group.teachers, group, payment.date, "TEACHER")`).
